**v0.1 | 2026-10-16** | 输入：`docs/whitepaper.md` v1.0 + 前任项目架构文档方法论（`.refinfo/VisiaEngine/docs/architecture.md`）
状态：**设计目标基线**（零代码）。图中全部组件均为设计意图，未实现；当前实际状态见 `.agents/memorys/status.md`；决策演进走 `.agents/memorys/decisions.md`（D1 已登记）。

## 设计不变量（高于所有图）

1. **JS 业务代码与渲染引擎隔离**：轻应用业务跑在 JS 引擎，渲染走独立引擎进程/线程，业务崩溃不拖垮渲染，GPU 上下文不属于业务沙箱（理由同前任"主循环属于宿主"——资源所有权决定崩溃域）。
2. **平台适配层是唯一平台 API 入口**：编译目标（微信/支付宝/飞书/快应用/自有容器/H5）的差异只通过适配层注入；业务代码零 `#ifdef` 泄漏（业务侧只见统一 API）。
3. **一套语义源，后端只加不改**：同一组件/DSL 语义在所有渲染路径（WebView/原生/自绘）行为一致；任何渲染后端不得引入业务层可见的新语义（前任教训：Unity 三管线互斥学费）。
   > 参照系实证（reference/ 调研，2026-10-16）：Hippy 3.x 以 Driver/DOM/Renderer 三层+可插拔 Renderer（Native/Flutter/Web 同接口）在多平台落地了同构纪律 → wry 标准模式与 wgpu HMI 模式应设计为**同一 Renderer 接口的两个实现**，布局留在共享的元素层；Lynx 的 gfx/display_list（OpType 枚举 + 序列化 Reader）证明该接口的交换格式用二进制指令流可行。
4. **容器 SDK 不劫持宿主主线程**：容器内 JS/渲染工作在自有线程/进程池，宿主 App 主线程只收事件回调（Flutter embedder ABI 纪律的同款）。
5. **离线包签名校验是硬边界**：任何代码进入沙箱前必须过签名+完整性校验；校验失败路径必须 fail-closed（拒绝运行），绝不 fail-open。
6. **Open Core 结构化隔离**：核心容器/编译引擎开源形态与商业套件（设计器/工业套件）通过模块边界隔离，依赖箭头单向。

## ② 模块依赖方向

```text
多端编译引擎 ──▶ 平台适配层(每目标平台一个) ──▶ 平台模板/运行时垫片
      │
      └──▶ 统一组件库(业务侧 API + 各平台实现) ──▶ 平台差异表

容器 SDK 内部：
  宿主 App(iOS/Android/Web)
      │  嵌入接口(UIView/VC · View/Fragment · WebComponent)
      ▼
  容器核心(生命周期/路由/多实例) ──▶ 沙箱与权限(签名/存储/网络白名单)
      │                                    │
      ▼                                    ▼
  JS 引擎适配(QuickJS/V8/Hermes 可插拔)   离线包管理(下载/校验/差分/回滚)
      │
      ▼
  渲染桥(命令流) ──▶ 高性能渲染引擎(WebGL/WebGPU/自绘) ──▶ 原生桥(平台能力)

铁律：依赖箭头单向向下；JS 引擎与渲染引擎通过渲染桥命令流通信，互不持有引用（不变量①）；
平台适配层之外任何模块不得 import 平台专有 API（不变量②）。
```

## ③ 一次轻应用启动的数据流

```text
宿主 App 启动 → 容器核心初始化 → 检查更新(管理后台)
     │                                    │
     │                              有新版: 差分下载 → 签名校验(fail-closed) → 静默切换
     ▼
打开轻应用 → 沙箱创建(权限集注入) → JS 引擎加载业务包 → 渲染桥建立
     │
     ▼
首帧渲染 → 页面路由 → 原生能力调用(异步批量, 经权限检查) → 埋点上行
     │
     ▼
前后台切换/销毁 → 状态持久化 → 沙箱销毁(存储隔离回收)
```

关键裁决占位（登记进 decisions.md 后回填编号）：
- JS 引擎选型（QuickJS vs V8 vs Hermes）——影响包体积/性能/调试体验
- 渲染后端分层（WebView 模式 vs 自绘模式的能力边界）
- 离线包格式与差分算法（影响更新流量与回滚速度）
- 沙箱权限模型（声明式清单 vs 运行时询问）

## ④ 多端编译模型

```text
统一源(DSL/TS + 组件树)
   │
   ├─ AST 解析 → 中间表示(IR)
   │     ├─ 条件编译: #ifdef 平台标记在 IR 层消解(不留在产物里)
   │     ├─ API 抹平: 调用统一 API → 适配层查表 → 平台专有实现
   │     └─ 组件多态: 同一组件名 → 每平台一张实现映射表
   │
   ├─ 平台代码生成: 微信(WXML/WXSS/JS) │ 支付宝 │ 飞书 │ 快应用(.rpk) │ H5
   │
   └─ 自有容器目标: 直接生成容器运行包 + 离线包格式 + 签名
```

不变量②的实现锚点：平台差异只出现在**编译期适配层**（微信编译目标/支付宝编译目标…），
业务 IR 中没有平台分支；运行期差异由各平台的运行时垫片吸收。

## ⑤ 宿主嵌入模型

```text
iOS:     宿主 VC ──▶ 容器 VC(嵌入形态A) / 容器 View(形态B)
Android: 宿主 Activity ──▶ 容器 Activity(形态A) / Fragment(形态B) / View(形态C)
Web:     iframe(形态A) / WebComponent(形态B)

线程契约（Flutter embedder 纪律同款）:
  宿主主线程 = 平台线程（容器不建自己的事件循环，不抢占）
  容器工作   = 自有线程池（JS 执行、渲染、下载互不阻塞宿主）
  跨线程通信 = 原生桥异步批量消息（支持背压，宿主可暂停容器）
```

## ⑥ 安全边界图

```text
┌─────────────── 宿主 App 信任域 ───────────────┐
│  宿主代码 · 宿主数据 · 原生能力                │
│      ▲                                        │
│      │ 权限检查(每调用) · 白名单(网络)          │
│ ┌────┴──────── 轻应用沙箱域 ────────┐          │
│ │ JS 引擎实例(每轻应用一个)          │          │
│ │ 存储: 独立沙箱目录                │          │
│ │ 代码: 签名校验后加载(fail-closed) │          │
│ └───────────────┬───────────────────┘          │
└─────────────────┼──────────────────────────────┘
                  │ 原生桥(唯一通道, 异步批量, 可审计)
                  ▼
            审计日志(敏感操作全记录)
```

不变量⑤的执行点：签名校验是进入沙箱域的唯一代码入口，无旁路。
